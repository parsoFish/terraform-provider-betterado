# Migrate all git resources and data sources to terraform-plugin-framework

> _Derived from `demo.json` (ADR 021). Essence:_ Six SDKv2 git resources/data-sources (betterado_git_repository resource+datasource, betterado_git_repository_branch resource, betterado_git_repository_file resource+datasource, betterado_git_repositories datasource) are now served by the mux provider via terraform-plugin-framework. All six types are deregistered from the SDKv2 ResourcesMap/DataSourcesMap and registered in framework_provider.go Resources()/DataSources(). Dead SDKv2 constructors and CRUD functions (ResourceGitRepository, DataGitRepository, DataGitRepositories) deleted along with orphaned SDKv2-era unit test files; shared helpers relocated to git_repository_helpers.go. Acceptance tests updated to use GetMuxedProviderFactories(). docs/git-gap-matrix.md produced. Registry docs regenerated via make docs. CHANGELOG updated and PROVIDER_VERSION.txt bumped to 1.2.1. framework-validators (listvalidator.SizeBetween, stringvalidator.OneOf, stringvalidator.RegexMatches, resourcevalidator.RequiredTogether) promoted to direct go.mod dependency and imported in resource_git_repository_framework.go.

### resource_git_repository_framework.go initialization block: validators implemented via terraform-plugin-framework-validators (direct go.mod dependency)

**Command:** `go build ./... && grep -r 'listvalidator\|stringvalidator\|resourcevalidator' azuredevops/internal/service/git/resource_git_repository_framework.go | wc -l`

- **Before:** Framework git_repository had hand-rolled validators — gitStringOneOfValidator, custom block-count check, custom ConfigValidate logic. terraform-plugin-framework-validators was `// indirect` in go.mod.
- **After:** Validators replaced: listvalidator.SizeBetween(1,1) for initialization block exactly-once; stringvalidator.OneOf for init_type and source_type; stringvalidator.RegexMatches for source_url URL format; resourcevalidator.RequiredTogether for parent_repository_id+initialization co-occurrence. terraform-plugin-framework-validators v0.19.0 promoted to direct go.mod dependency; go mod vendor re-synced.

### Dead SDKv2 constructors and CRUD functions deleted; shared helpers relocated to git_repository_helpers.go

**Command:** `git ls-files azuredevops/internal/service/git | grep -vE 'framework|helper'`

- **Before:** resource_git_repository.go, data_git_repository.go, data_git_repositories.go, resource_git_repository_test.go, data_git_repository_test.go, data_git_repositories_test.go existed under azuredevops/internal/service/git/ with dead SDKv2 constructors/read functions.
- **After:** All SDKv2 constructors (ResourceGitRepository, DataGitRepository, DataGitRepositories) and CRUD/read functions deleted. SDKv2-era unit test files deleted. Shared helpers (waitForBranch, initializeGitRepository, updateIsDisabledGitRepository, getGitRepositoriesByNameAndProject, repoInitializationMeta) live in git_repository_helpers.go.

### Acceptance tests use real test function names that exist in the repo; live run skipped (no TF_ACC credentials in build environment)

- **Before:** testEvidence cited fabricated *Framework test names (TestAccGitRepositoryFramework, TestAccDataGitRepositoryFramework, etc.) that do not exist in the repo.
- **After:** testEvidence updated to cite real test functions: TestAccGitRepository_withDefaultBranch, TestAccGitRepositoryBranch_fromBranch, TestAccGitRepoFile_basic, TestAccGitRepositoryFile_DataSource, TestAccDataSourceGitRepositories, TestAccGitRepository_DataSource. All six live-acceptance entries are honestly marked 'skip' — no TF_ACC credentials available in this build environment.
