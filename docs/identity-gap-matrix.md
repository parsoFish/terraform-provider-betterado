---

## Overview

This matrix compares every field returned by the ADO Identity REST API v7.1 (as reflected in the Go SDK models in `vendor/github.com/microsoft/azure-devops-go-api/azuredevops/v7/identity/models.go`) against what is currently exposed by the provider data sources in `azuredevops/internal/service/identity/`.

The Identity API uses the `Identity` struct (distinct from the Graph API's `GraphGroup` / `GraphUser` structs). It is accessible via `clients.IdentityClient` (wraps `ReadIdentity`, `ReadIdentities`, `ListGroups`).

Coverage status values:
- **covered** — field is covered in the TF schema and correctly wired
- **gap** — field is in the API response but absent from the TF schema (and would be useful to expose)
- **deferred** — field is in the API response but intentionally excluded (with rationale)

## 1. Identity struct (common to all identity API responses)

The `Identity` struct is the canonical ADO type for both identity groups and identity users:

```go
type Identity struct {
    CustomDisplayName *string
    Descriptor        *string
    Id                *uuid.UUID
    IsActive          *bool
    IsContainer       *bool
    MasterId          *uuid.UUID
    MemberIds         *[]uuid.UUID
    MemberOf          *[]string
    Members           *[]string
    MetaTypeId        *int
    Properties        interface{}
    ProviderDisplayName *string
    ResourceVersion   *int
    SocialDescriptor  *string
    SubjectDescriptor *string
    UniqueUserId      *int
}
```

## Writable Gaps — Implementation Decision (AC3)

All identified gaps are **read-only computed fields** returned by the Identity API. None involve write/create paths (the Identity API does not support creating or modifying identity objects directly via these endpoints — that is handled by the Graph API for groups and by the user-entitlement resources for users).

### Gaps to implement in this initiative:

| Gap | Resource/Data Source | Decision | Rationale |
|---|---|---|---|
| `provider_display_name` output attribute | `betterado_identity_group` | **implement in this initiative** | The display name is already the lookup key (`name`) but not returned as a computed output; consumers need it for cross-referencing |
| `is_active` | `betterado_identity_group` | **implement in this initiative** | Active flag is returned by `ReadIdentity`; useful for health-check data sources |
| `is_container` | `betterado_identity_group` | **implement in this initiative** | Always `true` for groups; useful as a type assertion in automation |
| `is_active` per item | `betterado_identity_groups` | **implement in this initiative** | Consistency with single-group data source; filters inactive groups in automation |
| `is_container` per item | `betterado_identity_groups` | **implement in this initiative** | Consistency with single-group data source |
| `provider_display_name` output attribute | `betterado_identity_user` | **implement in this initiative** | Display name available but not returned as output attribute |
| `is_active` | `betterado_identity_user` | **implement in this initiative** | Useful for detecting disabled/inactive accounts |

### Deferred gaps (not in scope for this initiative):

| Gap | Rationale for deferral |
|---|---|
| `memberIds`, `memberOf`, `members` on groups | Complex nested types; consumers should use dedicated `betterado_group_membership` / `betterado_identity_groups` data sources for membership queries |
| `properties` on all types | Opaque property bag (`interface{}`); schema varies per identity type; not suitable for typed TF attributes without significant schema design work |
| `customDisplayName` | Custom override display name; rarely populated in practice; low consumer value |
| `masterId`, `metaTypeId`, `resourceVersion`, `uniqueUserId` | Internal system fields not documented in public ADO REST API reference; no consumer value in IaC |
| `socialDescriptor` | MSA-specific descriptor; low relevance for AAD-backed organizations which are the primary use case |
| `isContainer` on user | Always `false` for user identities; not meaningful to expose |
| `memberIds`, `memberOf`, `members` on user identity | Not applicable or always empty for non-container identity objects |
