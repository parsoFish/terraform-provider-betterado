# betterado_release_definition_permissions (Resource)

Manages Azure DevOps security permissions for a classic release definition using
the `ReleaseManagement2` security namespace
(`c788c23e-1b46-4162-8f5e-d7585343b5de`).

Permissions are applied as Access Control Entries (ACEs) on an Access Control
List (ACL) scoped to the token `{projectId}/{releaseDefinitionId}`. When
`release_definition_id` is omitted the token collapses to just `{projectId}`,
granting or restricting permissions across **all** release definitions in the
project.

## Usage

### Available permission keys

All permission keys correspond to the `ReleaseManagement2` namespace action
definitions confirmed via live ADO probe
(`_apis/accesscontrollists/c788c23e-1b46-4162-8f5e-d7585343b5de`).

| Key | Bit | Description |
|---|---|---|
| `ViewReleases` | 1 | View the release list and release details |
| `EditReleaseEnvironment` | 2 | Approve or reject an environment deployment |
| `DeleteReleases` | 4 | Delete a release |
| `ManageReleasesSettings` | 8 | Manage release settings for the definition |
| `ViewReleasePipeline` | 16 | View the release pipeline definition |
| `EditReleasePipeline` | 32 | Create, edit, and save a release definition |
| `DeleteReleasePipeline` | 64 | Delete a release definition |
| `ManageReleaseApprovers` | 128 | Manage release approvers |
| `CreateReleases` | 256 | Trigger a new release |
| `QueueRelease` | 512 | Queue a release or deploy to an environment |
| `AdministerReleasePermissions` | 1024 | Administer release permissions (manage ACEs) |
| `ManageDeployments` | 4096 | Manage deployments (view/approve stage gates) |

Permission values are `"Allow"`, `"Deny"`, or `"NotSet"` (removes an explicit
entry, inheriting from the namespace default).

### Token format

| Scope | Token format | When to use |
|---|---|---|
| Definition-level | `{projectId}/{releaseDefinitionId}` | Permissions on one release definition |
| Project-level | `{projectId}` | Permissions across all definitions in the project |

Set `release_definition_id` to scope to a specific definition; omit it for
project-level permissions.

### Example — all writable permission keys

```hcl
resource "betterado_project" "project" {
  name               = "my-project"
  visibility         = "private"
  version_control    = "Git"
  work_item_template = "Agile"
}

resource "betterado_release_definition" "release" {
  project_id = betterado_project.project.id
  name       = "my-release-pipeline"

  environment {
    name = "Production"
    rank = 1

    deploy_phase {
      name       = "Agent job"
      rank       = 1
      phase_type = "agentBasedDeployment"
    }

    retention_policy {
      days_to_keep     = 30
      releases_to_keep = 3
      retain_build     = true
    }

    pre_deploy_approval {
      approver {
        id           = "00000000-0000-0000-0000-000000000000"
        is_automated = true
        rank         = 1
      }
    }

    post_deploy_approval {
      approver {
        id           = "00000000-0000-0000-0000-000000000000"
        is_automated = true
        rank         = 1
      }
    }
  }
}

data "betterado_group" "readers" {
  project_id = betterado_project.project.id
  name       = "Readers"
}

resource "betterado_release_definition_permissions" "permissions" {
  project_id            = betterado_project.project.id
  principal             = data.betterado_group.readers.id
  release_definition_id = betterado_release_definition.release.id

  permissions = {
    ViewReleases                 = "Allow"
    EditReleaseEnvironment       = "Deny"
    DeleteReleases               = "Deny"
    ManageReleasesSettings       = "Allow"
    ViewReleasePipeline          = "Allow"
    EditReleasePipeline          = "Allow"
    DeleteReleasePipeline        = "Deny"
    ManageReleaseApprovers       = "NotSet"
    CreateReleases               = "Allow"
    QueueRelease                 = "Allow"
    AdministerReleasePermissions = "Deny"
    ManageDeployments            = "Allow"
  }
}
```
