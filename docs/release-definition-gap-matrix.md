## 2. Data Source Coverage

### 2.1 SDK Client Methods vs Surfaced Data Sources

The SDK `Client` interface (vendor/…/release/client.go) exposes these read-relevant methods:

| SDK method | Surfaced by data source? | Verdict |
|---|---|---|
| `GetReleaseDefinition` | ✅ Yes — `data_release_definition.go` (lookup by ID or name via `GetReleaseDefinitions`) | Surfaced |
| `GetReleaseDefinitions` | ✅ Yes — `data_release_definitions.go` (list, optionally filtered by path/name) | Surfaced |
| `GetDefinitionRevision` | ❌ No | **Recommend** — useful for auditing/diff against a specific historical snapshot |
| `GetReleaseDefinitionHistory` | ❌ No | **Recommend** — surfaces revision log (who changed what, when) |
| `GetRelease` | ❌ No | Defer — release instances are a separate domain |
| `GetReleases` | ❌ No | Defer — release instances |
| `GetReleaseEnvironment` | ❌ No | Defer — runtime environment state |
| `GetApprovals` | ❌ No | Defer — runtime approval state |
| `GetDeployments` | ❌ No | Defer — runtime deployment state |

### 2.2 Data Source Gap Verdicts

| Gap | Verdict | Rationale |
|---|---|---|
| `GetDefinitionRevision` — return specific revision JSON | **Recommend** | Enables version-pinning and auditability in IaC; low complexity (returns `io.ReadCloser`) |
| `GetReleaseDefinitionHistory` — return revision list | **Recommend** | Enables change-history data sources for compliance dashboards |
| `GetRelease` / `GetReleases` | **Defer** | Release instances (not definitions) are out of scope for IaC lifecycle |
| `GetReleaseEnvironment` | **Defer** | Runtime state; not TF-lifecycle-relevant |
| `GetApprovals` / `GetDeployments` | **Out of scope** | Runtime operations data; not suitable for declarative IaC |

### 2.3 Current Data Source Schema Gaps

The existing `data_release_definition` data source only surfaces **4 fields** (`name`, `path`, `description`, `release_name_format`) plus `project_id` and `release_definition_id`. It does **not** surface:

- `environments`, `artifacts`, `triggers`, `variables`, `variable_groups`, `revision`, `tags`

> **Verdict:** The data source is a **stub** sufficient for cross-definition references. A full read-back data source (matching the resource schema) is a **Recommend** for a future WI.
