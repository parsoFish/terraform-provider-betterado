### Writable gaps and their dispositions

All writable gaps are explicitly deferred with rationale:

1. **`betterado_project.abbreviation`** — ADO Projects API supports a short abbreviation string on the project object. Writable via Update. **Deferred:** field is rarely configured in IaC (typically auto-derived or not needed); no known user request. Will be addressed in a separate enhancement WI.

2. **`betterado_project_pipeline_settings.disableClassicBuildPipelineCreation`** — Controls creation of classic (non-YAML) build pipelines. **Deferred:** policy enforcement field; requires a separate focus WI to audit all pipeline-settings booleans added since ADO v7.0. Low risk from omission since classic pipelines are being deprecated.

3. **`betterado_project_pipeline_settings.disableClassicReleasePipelineCreation`** — Same category as above. **Deferred:** same rationale.

4. **`betterado_project_pipeline_settings.enforceNoAccessToSecretsFromForks`** — Security control for fork PR pipelines. **Deferred:** security-hardening setting; implement as part of a dedicated security-settings WI to ensure test coverage is correct.

5. **`betterado_project_pipeline_settings.isCommentRequiredForPullRequest`** — Requires comment resolution before PR merge. **Deferred:** PR policy setting at project scope; low priority relative to pipeline-security concerns; implement in follow-up WI.
