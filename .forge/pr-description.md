## Why

The betterado Terraform provider still served its security, securityroles, and permissions resources through the legacy SDKv2 helper layer (`ResourcesMap` / `DataSourcesMap`). Remaining on SDKv2 blocks adoption of framework-only features (plan modifiers, diagnostics, typed models), creates two provider-data paths to maintain, and prevents the mux provider from routing these resources through the ProtoV6 server. This initiative completes the migration for the remaining 17 resource types (1 security resource + 3 security data sources + 1 securityroles resource + 1 securityroles data source + 13 permissions resources) and delivers gap matrix docs for all three packages. A follow-up code fix (UWI-6) also deleted 11 orphaned SDKv2-era unit test files that referenced symbols removed during the dedup step, restoring `-tags all` compilation across all three service packages.

## What

- **Gap matrices** (`docs/security-gap-matrix.md`, `docs/securityroles-gap-matrix.md`, `docs/permissions-gap-matrix.md`): compare each package's SDKv2 schema against the ADO REST API v7.1; mark every writable gap as resolved or deferred.
- **Security package migration** (`azuredevops/internal/service/security/`): `betterado_security_permissions` resource and `betterado_security_namespace`, `betterado_security_namespace_token`, `betterado_security_namespaces` data sources all re-implemented as `provider.Resource` / `datasource.DataSource`. Deregistered from `provider.go`; added to `framework_provider.go`.
- **Securityroles package migration** (`azuredevops/internal/service/securityroles/`): `betterado_securityrole_assignment` resource and `betterado_securityrole_definitions` data source re-implemented with framework. Handles ADO inherited-access-after-delete edge case.
- **Permissions package migration** (`azuredevops/internal/service/permissions/`): 13 resources (`betterado_area_permissions`, `betterado_build_definition_permissions`, `betterado_build_folder_permissions`, `betterado_git_permissions`, `betterado_iteration_permissions`, `betterado_library_permissions`, `betterado_project_permissions`, `betterado_serviceendpoint_permissions`, `betterado_servicehook_permissions`, `betterado_tagging_permissions`, `betterado_variable_group_permissions`, `betterado_workitemquery_permissions`, `betterado_workitemtrackingprocess_process_permissions`) each receive a `*_framework.go` implementation; all deregistered from SDKv2.
- **Provider registration** (`azuredevops/provider.go`, `azuredevops/internal/provider/framework_provider.go`, `azuredevops/provider_test.go`): 14 resource types and 4 data sources removed from SDKv2 maps; counts updated in `provider_test.go`.
- **Acceptance tests**: `TestAccSecurityPermissionsFramework`, `TestAccSecurityroleAssignmentFramework`, `TestAccProjectPermissionsFramework` — each verifies apply → read-back → idempotency re-plan → destroy using `GetMuxProviderFactories()`. Existing permissions acceptance tests updated to use `GetMuxProviderFactories()`.
- **Compile fix** (UWI-6): 11 orphaned SDKv2-era test files deleted from `azuredevops/internal/service/permissions/`, `azuredevops/internal/service/security/`, and `azuredevops/internal/service/securityroles/`. These files referenced symbols (`ResourceSecurityRoleAssignment`, `DataSecurityNamespaceToken`, `createBuildDefinitionToken`, etc.) that were removed when the SDKv2 source files were deleted during the dedup step, causing `-tags all` compilation to fail across all three packages. Deletion restores `go vet -tags all` and `go test -tags all` to a clean state.
- **Docs + examples**: `make docs` re-run; `docs/guides/` restored; `examples/resources/` and `examples/data-sources/` created for all migrated types.
- **CHANGELOG.md + PROVIDER_VERSION.txt**: draft Unreleased entries for all 17 user-visible migrations; version bumped to `1.3.0`.

## How

Each migration follows the established pattern from `resource_release_definition_permissions_framework.go`:

1. Create `*_framework.go` alongside the existing SDKv2 file (SDKv2 file kept for reference/rollback).
2. Implement `provider.Resource` / `datasource.DataSource` with a `model` struct using `tfsdk` tags mirroring the SDKv2 schema shape exactly.
3. Wire `*client.AggregatedClient` in `Configure()` from `req.ProviderData`.
4. Replicate CRUD logic from the SDKv2 source: for security permissions — resolve identity descriptor → compute ACE bitmasks → `SetAccessControlEntries` → poll sync; for securityroles — `SetSecurityRoleAssignment` + poll; for all permissions resources — use `securityhelper.NewSecurityNamespace` + `SetPrincipalPermissions` / `GetPrincipalPermissions` with inline token computation.
5. Remove each type from `provider.go` `ResourcesMap`/`DataSourcesMap`; add `New<Type>Resource()` / `New<Type>DataSource()` constructors to `framework_provider.go`.
6. Update `provider_test.go` resource/data-source count lists.
7. Write acceptance test using `GetMuxProviderFactories()` with `ExpectNonEmptyPlan: false` idempotency step; call `CaptureLiveEvidence("acceptance-resource", url, nil)` in the read-back step.
