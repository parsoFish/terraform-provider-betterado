## Why

The betterado Terraform provider had no support for Azure DevOps notification subscriptions. Teams managing ADO notification subscriptions via the REST API had to do so outside Terraform, breaking infrastructure-as-code parity. This initiative maps the full ADO Notifications REST API v7.1 surface (gap matrix), then implements `betterado_notification_subscription` as a framework-native resource and companion data source, verified by a live acceptance test against a real ADO organisation.

## What

- **`docs/notification-gap-matrix.md`** — 335-line catalogue of every `NotificationSubscription` field with implement / read-only / out-of-scope status and explicit rationale. `NotificationSubscriptionTemplate` triaged as out-of-scope (deferred data source); serves as the shared contract between analysis and implementation.
- **`azuredevops/internal/client/client.go`** — `AggregatedClient` gains `NotificationClient notification.Client` field; `GetAzdoClient` initialises it from the connection.
- **`azuredevops/internal/service/notification/resource_notification_subscription_framework.go`** — framework `resource.Resource` with schema fields `project_id`, `subscription_type`, `subscriber_id`, `channel_type`, `channel_address`, `filter_type`, `filter_criteria`, `status`; CRUD via `NotificationClient.*Subscription`; Read returns `nil` (remove from state) on 404.
- **`azuredevops/internal/service/notification/data_notification_subscription_framework.go`** — framework `datasource.DataSource`; reads subscription by ID; all attributes computed.
- **`azuredevops/internal/provider/framework_provider.go`** — `Resources()` and `DataSources()` each gain one entry for the new notification types. Zero touches to `azuredevops/provider.go` (SDKv2).
- **`azuredevops/internal/service/notification/resource_notification_subscription_framework_test.go`** — unit tests `TestNotificationSubscriptionResource_Create` and `TestNotificationSubscriptionResource_Read` using gomock; cover expand/flatten round-trips for all six schema fields.
- **`azuredevops/internal/acceptancetests/resource_notification_subscription_test.go`** — live acceptance test `TestAccNotificationSubscription_basic`: apply → read back → idempotency re-plan (`ExpectNonEmptyPlan: false`) → destroy; calls `CaptureLiveEvidence("acceptance-resource", url, response)`.
- **`examples/resources/betterado_notification_subscription/resource.tf`** and **`examples/data-sources/betterado_notification_subscription/data-source.tf`** — non-trivial HCL examples embedded in the registry docs.
- **`docs/resources/notification_subscription.md`** and **`docs/data-sources/notification_subscription.md`** — generated by `make docs` (tfplugindocs); hand-written guides restored via `git checkout -- docs/guides/`.
- **`CHANGELOG.md`** — draft `## [Unreleased]` entry added (FEATURES: `betterado_notification_subscription` resource and data source).
- **`PROVIDER_VERSION.txt`** — bumped to `1.2.1`.

## How

1. **Gap matrix first (WI-1):** read vendored SDK `notification/models.go` and `client.go` + mock interface; assigned status to every field before writing a line of implementation code.
2. **Client wiring + resource (WI-2):** extended `AggregatedClient`; wrote the framework resource with `expandNotificationSubscription` / `flattenNotificationSubscription` helpers and gomock unit tests covering all fields; registered in `framework_provider.go` only.
3. **Data source + live gate + docs (WI-3):** implemented the data source; wrote `TestAccNotificationSubscription_basic` against `betterado-standing-demo` project (no project creation); captured live evidence (subscription 886543, `ms.vss-work.workitem-changed-event`, `EmailHtml` channel, `abby@kel.so`) at `capturedAt: 2026-07-03T06:37:04Z`; ran `make docs` + restored guides; updated CHANGELOG and PROVIDER_VERSION.txt.
4. **Unifier (this PR):** quality gate (`go test -tags all -count=1 ./azuredevops/internal/service/release/... ./azuredevops/internal/service/taskagent/...`) confirmed green; all 10 initiative ACs verified against branch tip.
