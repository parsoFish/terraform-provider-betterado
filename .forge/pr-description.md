## Why

The pure-framework provider (post mux-free cutover, v2.0.0) accepted 17 AAD/OIDC/MSI/CLI schema attributes but `Configure()` only read `org_service_url` and `personal_access_token`. Every non-PAT caller — Azure CLI, MSI, OIDC, client-secret service-principal — received `resp.ResourceData = nil`, silently breaking all 68 resources and 41 data sources for those credential methods. A secondary security gap existed: explicit `use_cli = false` in HCL was silently overridden to `true` by the ARM_USE_CLI default path because UseCLI was stored as `bool` (zero-value = false was indistinguishable from "unset"). The working logic existed in the SDKv2-only `GetAuthProvider()` in `provider.go` but was never ported to the framework path. This initiative closes both gaps: all 17 credential methods now resolve correctly in the framework `Configure()`, `use_cli = false` is honoured, a fail-fast diagnostic fires when no credential is configured, malformed bool env vars surface a warning diagnostic instead of silently resetting, and the provider declares protocol 6.0 for the Terraform 1.x handshake.

## What

- **`azuredevops/internal/provider/auth.go`** — new `FrameworkAuthConfig` struct (with `UseCLI *bool` for null/false distinction) and `resolveFrameworkAuthProvider(ctx, cfg)` covering all five credential methods (PAT, Azure CLI via aztfauth, MSI, client-secret AAD, OIDC) with full AZDO_*/ARM_*/AZURE_* env-var fallbacks. `use_cli` defaults to `true` when `ARM_USE_CLI` is unset but `false` is preserved when HCL explicitly sets it. `ARM_AUXILIARY_TENANT_IDS` values are whitespace-trimmed after comma-split. `parseBoolEnv` returns a warning string for malformed values instead of silently treating them as unset.
- **`azuredevops/internal/provider/auth_test.go`** — 9 unit tests (`TestResolveFrameworkAuth_*`) covering every credential path, env-var fallback, the no-credential error, and the `use_cli=true` default. No live ADO calls.
- **`azuredevops/internal/provider/framework_provider.go`** — `Configure()` replaced: reads all 17 schema attributes (using `types.Bool.IsNull()` to distinguish unset from explicit false for `use_cli`), builds `FrameworkAuthConfig`, threads `parseBoolEnv` warnings up to `resp.Diagnostics.AddWarning`, on auth error adds an actionable `AddError` diagnostic naming all available credential options, on success calls `client.GetAzdoClient` and stores `*client.AggregatedClient` in both `resp.ResourceData` and `resp.DataSourceData`. Stale SDKv2/mux comments swept from `Configure()` body and schema doc strings.
- **`azuredevops/internal/provider/framework_provider_test.go`** — two new tests: `TestFrameworkConfigure_PAT` and `TestFrameworkConfigure_NoCredential` (asserts `Diagnostics.HasError() = true` with the no-credential error message).
- **`azuredevops/internal/acceptancetests/resource_provider_auth_test.go`** — `TestAccAuthParity_CLIPath` (live, probes az CLI for ADO-audience token; skips with `t.Skipf` if unavailable, uses `t.Setenv` for automatic env restore) and `TestAccAuthParity_CredentialConstruction` (always runs; proves 6 credential-construction paths without a live ADO call: ClientSecret, OIDCToken, OIDCTokenFile, OIDCTokenRequest, CLI, MSI). ClientCertificate excluded from construction test: aztfauth requires real PEM/PFX data at construction time (getClientCert() fails eagerly on empty input). Uses `GetProviderFactories()` (ProtoV6), references `SharedFixtureProjectName`, never creates new ADO projects. Calls `testutils.CaptureLiveEvidence("acceptance-auth-parity", ...)` when live.
- **`terraform-registry-manifest.json`** — `protocol_versions` changed from `["5.0"]` to `["6.0"]`.
- **`PROVIDER_VERSION.txt`** — bumped from `2.0.0` to `2.0.1`.
- **`CHANGELOG.md`** — draft `## 2.0.1 (Unreleased)` section added with ENHANCEMENTS for auth parity, protocol 6.0, auxiliary tenant ID trimming, and parseBoolEnv warning surfacing.

## How

The implementation follows the architecture decision recorded in the initiative manifest: extract a shared `resolveAuthProvider` helper (in `auth.go`) that both `Configure()` and unit tests import, avoiding duplication of the `aztfauth.Option` struct wiring. The credential priority order mirrors `GetAuthProvider()` in `provider.go`: PAT first (returns `AuthProviderPAT` directly), then all other methods routed through `aztfauth.NewCredential` wrapped in `AuthProviderAAD` with scope `499b84ac-1321-427f-aa17-267ca6975798/.default`. The no-credential error from `resolveFrameworkAuthProvider` bubbles up to `Configure()` as an `AddError` diagnostic naming all available options. The `use_cli` null/false distinction is preserved via `*bool` in `FrameworkAuthConfig` — `framework_provider.go` checks `types.Bool.IsNull()` before populating the pointer, so an absent HCL attribute triggers the `ARM_USE_CLI` default path while `use_cli = false` sets the pointer to `false` and skips the default. The live acceptance test probes az CLI availability with a single `az account get-access-token --resource 499b84ac-1321-427f-aa17-267ca6975798` call and immediately skips if non-zero (per operator note: az is installed but logged into the wrong tenant and cannot mint ADO-audience tokens). The hollow gate (`go test -tags all -run TestAccAuthParity ./azuredevops/internal/acceptancetests/` without `TF_ACC`) exits 0 via `t.Skip`.
