## Key patterns / lessons learned

### ADO Notification API quirks
- `ISubscriptionFilter` and `ISubscriptionChannel` Go structs are interface types — they only carry `Type` and `EventType` fields. `ChannelAddress` and `FilterCriteria` are NOT returned by the API wrapper — must keep model value if already known, set to `types.StringNull()` if unknown.
- ADO soft-deletes subscriptions: after DELETE, status transitions to `pendingDeletion` before physical removal. `Read` and `CheckDestroy` must treat this as "gone".
- `Status` field: after Create it can be "enabled" immediately; type is `*SubscriptionStatus` (enum string).

### Framework / Terraform plugin patterns
- Every Computed (or Optional+Computed) field MUST be set to a known value after Create/Read. The `flattenNotificationSubscription` function handles `IsUnknown()` → `types.StringNull()` for fields the API doesn't return.
- Plan modifiers: `notifRequiresReplace` for `project_id`, `notifUseStateForUnknown` for computed-but-API-opaque fields.
- Data source: `id` is Required (user provides it to look up); all other fields are Computed.

### Acceptance test pattern
- `resolveNotificationSubscriberDirect` auto-discovers a real ADO user with MailAddress via `GraphClient.ListUsers` paging + `IdentityClient.ReadIdentities(SearchFilter="MailAddress")`. Avoids AZDO_TEST_AAD_USER_EMAIL dependency.
- `SharedFixtureProjectName` from `testutils` for the project name.
- `testutils.CaptureLiveEvidence("acceptance-resource", url, sub)` writes to `.forge/live-evidence/acceptance-resource.json`.

### CI gate gotchas
- `make test` without `TF_ACC` skips acceptance tests, prints `ok ... 0.00s` — NOT a live gate pass.
- golangci-lint v2 (`--new-from-rev=main`) — only new issues matter.
